# Промпты для агента: дерево черт Поборника (PF2e)

Рабочая тетрадь агента: готовые промпты, разбитые на исполнительные блоки.
Каждый блок можно отдать агенту отдельно. В блоке есть цель, входные данные, сам промпт, шаги, критерии готовности и грабли, на которые уже наступали.
Блоки собраны из того, что обсуждалось и делалось в проекте. Порядок блоков соответствует порядку работы.

### Принятые решения (не пересматривать без запроса)

| Тема | Решение |
|---|---|
| Источник данных | pf2.ru: JSON в атрибуте `items` у `<pf2-table>` на странице класса и `/viewbox/<тип>/<id>?lang=ru` для описаний. Meilisearch-API сайта требует ключ — **не использовать**. |
| Когда грузить данные | При сборке, а не в браузере: у pf2.ru нет CORS, и приложение должно работать офлайн. |
| Связи | Только реальные критерии черт. Освящение показывается значком на узле, а не линией. Условие «одно из вариантов группы» рисуется одной пунктирной связью от группы. |
| Ветка `tree-trunk` (альтернатива) | Вместо колец — дерево от корня (`tools/tree-layout.mjs`): корень → шина → 9 узлов-тем → у каждой темы вертикальный ствол, черты слева и справа по возрастанию уровня, у черты с детьми свой короткий ствол наружу. Половина тем растёт вверх, половина вниз. Аура поборника и Блок щитом **не узлы** (гарантированы), их условия считаются выполненными. Связи между чертами — только основные (вторая черта-критерий, например «любая клятва», — в подсказке). Уровень черты — число на узле. |
| Выбор при создании | Освящение, призвание, заклинание преданности и благословение показаны **карточками в верхней панели**, а не узлами на холсте. Требование такой карточки показано на черте маленьким медальоном слева сверху (золотой, если выполнено). В раскладке узлы-карточки скрыты (`isCardNode`). |
| Раскладка | Узел стоит на кольце своего уровня и в одном из 40 угловых слотов. Цепочки почти прямые. 0 пересечений, 0 рёбер через узлы, 0 задетых подписей. |
| Шаг на кольце | Одинаковый **внутри ветки**, между ветками — промежутки. Строго равномерный шаг по всей окружности отвергнут: даёт 65+ пересечений. |
| Подписи | У каждого узла, кроме центрального. Позицию выбирает раскладка из 8 вариантов, ширина фиксирована данными. |
| Git | В коммитах **нет** строки соавторства. Без запроса не коммитить и не пушить. Если ветка по умолчанию — сначала создать отдельную ветку. |
| GitHub | origin = FeatTreeChampionTest. Remote `champion` = ClassSkillTreeChampionPf2e, туда запушена ветка `feat-tree-redesign`. У неё нет общей истории с `main` этого репозитория. |

**Цель:** найти машиночитаемый путь к чертам, критериям и описаниям.

```text

Найди, откуда приходят данные таблицы черт: сетевые запросы и встроенный в HTML JSON.
```

**Готово, когда:** известны поля строки таблицы (`id`, `rus_name`, `level_sort`, `prerequisites` с `data-key="feat/N"` …) и формат вьюбокса.

- `<pf2-table items='[...]'>` — 71 черта и 6 заклинаний;

- разделы «Освящение», «Аура поборника», «Благословение верного» берутся со вкладки `?tab=details` по якорям `id="…"`;
- значки действий: `action-icon` 1/2/3 — действия, 4 — свободное, 5 — ответное.


## Блок 4. Сборка графа и ручные правила (`tools/build-graph.mjs`)

```text
Преврати сырые данные в граф. Типы узлов:
- root;
- group: Освящение / Призвание / Заклинания преданности / Благословение верного;
- option: варианты внутри групп;
- feature: Аура поборника, Блок щитом — есть у всех;
- feat: черты.
Требования храни как requires = [[a,b],[c]], то есть (a ИЛИ b) И c, и forbids = [x].
Разбирай критерии по ссылкам (feat/spell/championcause/trait) и по ключевым словам в тексте.
Всё, что не распозналось, печатай как предупреждение.
Ручные исправления складывай в OVERRIDES по английскому имени, картинки — в FEAT_IMAGES.
```

**Готово, когда:** сборка проходит без предупреждений, а каждая черта с критериями получила `requires`.
**Ручные правила, которые уже нужны:**
- Призвания по освящению: Величие и Искупление требуют «священный», Осквернение и Беззаконие — «нечестивый», остальные доступны при любом освящении.
- «Аура веры»: на сайте «священный **и** нечестивый», по смыслу «или».
- «Самопожертвование поборника»: запрет для нечестивого освящения (`forbids`).
- «Щитоносец»: в критериях смешаны Воин и старая редакция. Правильно: Блок щитом + благословенный щит.
- Ответные действия: «устойчивость к урону» — Величие, Искупление, Правосудие, Освобождение; «доп. урон» — Беззаконие, Осквернение, Повиновение.
- «Божественная преграда»: «You're wielding a shield» — это требование, а не критерий.
- Блок щитом (feat 5212) — классовая особенность, а не выбираемая черта.

## Блок 5. Приложение: логика сборки персонажа (`app.js`)

```text
Реализуй правила выбора:
- ячейки черт класса — на 1-м и каждом чётном уровне; вместимость проверяй жадным распределением черт по слотам;
- в группах освящения, призвания и заклинания преданности выбор взаимоисключающий: новый вариант заменяет старый;
- благословение доступно с 3-го уровня, второе — только с чертой «Второе благословление»;
- при снятии узла или понижении уровня каскадно снимай всё, что перестало подходить, и сообщай об этом в тосте;
- сохраняй сборку в localStorage (через try/catch) и делай ссылку вида #b=уровень.id,id.
HTML описаний вставляй только через санитайзер со списком разрешённых тегов. Ссылки разрешены только на https://pf2.ru, с target=_blank и rel=noopener.
```

**Готово, когда:** сценарий «нечестивое освящение → призвание Величие» блокируется, а смена освящения каскадно снимает призвание и его черты.

## Блок 7. Раскладка без наложений и пересечений (`tools/layout.mjs`)

```text
Перенеси раскладку в сборку. Координаты, сторону подписи и её ширину записывай в данные.
Приложение только читает готовые x и y.
Целевые метрики, которые печатаются в консоль:
- пересечений 0, рёбер через узлы 0, наложений 0, задетых подписей 0;
- изломов цепочек больше 45° — 0 или 1;
- разрывов в ветках — минимум.
Метод: имитация отжига на дискретной угловой сетке (GRID = 40 слотов). Радиус задаётся уровнем.
Ходы: перенос узла в соседний слот или обмен с узлом в этом слоте; смена стороны подписи (8 позиций).
Перебери несколько seed и возьми лучший по score. Если score равен 0, останавливайся сразу.
```

**Штрафы, которые уже настроены** (`W` в начале файла):
- наложение узлов;
- пересечение рёбер (×9000);
- ребро через узел;
- ребро или узел поверх подписи;
- слияние рёбер, выходящих под углом меньше 15°;
- излом цепочки родитель → узел → ребёнок больше 17° (штраф квадратичный);
- разрыв между соседями одной ветки;
- длина рёбер (слабый);
- уход от тематического сектора (слабый).

**Грабли из опыта:**
- Строго равномерный шаг по всей окружности даёт 65+ пересечений. Свободный шаг с жёстким выравниванием внутри ветки даёт 10–30 пересечений. Сетка слотов даёт 0.
- Без противовеса штраф за разрывы в ветке сбивает кольцо в один сектор (на 18 уровне было 5 узлов в 54°, остальные 306° пусты). Противовес — штраф за пустоту больше `GAP_MAX` идеальных шагов `2π/m` (`W.gap`) и за смещение центра тяжести (`W.balance`). Сектора в начальной раскладке считаются только по видимым узлам: у карточек вес 0.
- Ширину подписи оценивай с запасом: `CHAR_W = 0.7` (замер в браузере — до 0.67). Приложение задаёт подписи **ровно эту ширину**, иначе отрисовка разойдётся с расчётом.
- Узлам без критериев не создавай ложных связей. Привязка через `LAYOUT_ANCHOR` влияет только на место узла, а пунктир от группы рисуется лишь при реальном «одном из вариантов».
- Ветку «Верный скакун» держи рядом с «Возложением рук» (через них идёт «Исцеление скакуна»), а «Блок щитом» — рядом с «Благословением».
- Сборка идёт 2–5 минут. Запускай её в фоне. Для перебора параметров используй скрипт, который гоняет `computeLayout` по списку seed. Параметры можно задать через окружение: `LAYOUT_GRID`, `LAYOUT_EVEN`, `LAYOUT_DEBUG=1` (печатает задетые подписи и изломы).
